# ИИ-игроки — модуль для Foundry VTT 13

Четыре ИИ-агента (Claude, API Anthropic) играют за четырёх персонажей. Мастер — человек: пишет сцену в чат, агенты отвечают там же от имени своих персонажей — спорят, задают вопросы мастеру, делают заявки. В конце обсуждения появляется карточка «Заявки группы».

Весь код работает в браузере мастера: без сервера, без сборщика, без SDK. Запросы идут напрямую на `https://api.anthropic.com/v1/messages`.

- Foundry VTT: 13.
- Система: Mongoose Traveller 2e (`mgt2e`, автор Samuel Penn / NotASnark). На других системах модуль тоже работает, но лист персонажа агент видит в минимальном виде (только имя и предметы).

## Установка

1. Скопируйте папку `ai-players` целиком в каталог модулей Foundry:
   `{данные пользователя Foundry}/Data/modules/ai-players/`. Внутри должен лежать `module.json`.
   Папка `tests/` и `package.json` для работы в Foundry не нужны, их можно не копировать.
2. Перезапустите Foundry (или вернитесь в меню и снова зайдите в мир).
3. В мире: **Настройки игры → Управление модулями** → включите «ИИ-игроки» → «Сохранить».
4. Откройте консоль браузера (F12). При загрузке модуль пишет:
   `ai-players | game.system.id = "mgt2e" (Mongoose Traveller 2e), Foundry 13.x`.
   Если id системы другой, модуль предупредит, что адаптера для неё нет.

Язык интерфейса модуля — русский. Файл `lang/ru.json` подключён и для английского интерфейса Foundry, чтобы при английском интерфейсе не показывались «сырые» ключи.

## Настройка

### API-ключ

**Настройки игры → Настройки модулей → ИИ-игроки → «API-ключ Anthropic».**

- Ключ хранится только в этом браузере (`scope: "client"`): в мир, в журналы и другим участникам он не попадает. Поэтому ключ вводит только мастер, и в каждом своём браузере отдельно.
- Поле ввода — как пароль.

### Остальные настройки (там же)

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Модель | `claude-sonnet-5-5` | Любой id модели Claude, меняется без правки кода |
| Усилие модели (effort) | `low` | Сколько модель «думает». Для коротких реплик хватает `low`. Для старых моделей без effort (например, `claude-haiku-4-5`) — «не отправлять» |
| Максимум кругов на сцену | 3 | |
| Максимум запросов на сцену | 16 | Жёсткий предел, повторы тоже считаются |
| Максимум токенов в ответе агента | 400 | `max_tokens` |
| Сообщений чата в контексте | 40 | Сколько последних видимых персонажу сообщений получает агент |
| Автоответ на сообщения мастера | вкл | Выключено — цикл только по `/ai go` |
| Показывать мысли агентов | вкл | Строку `thought` («почему так») мастер получает шёпотом |

Для `claude-sonnet-5-5` модуль отправляет `thinking: {type: "between_tools"}`: это режим без расширенного размышления, и бюджет в 400 токенов целиком уходит на ответ. Если поставите другую модель, она по умолчанию может думать, а размышление тоже тратит `max_tokens`. Если ответы начнут обрываться (мастеру придёт шёпот «ответ обрезан лимитом токенов»), увеличьте «Максимум токенов» до 800–1500.

### Агенты

**Настройки модулей → ИИ-игроки → «Настроить агентов».** Четыре слота:

- **Актёр** — за кого играет агент. Для `mgt2e` в списке только актёры типов `traveller` и `npc`.
- **Паспорт персонажа** — свободный текст: цель, страхи, слабость, манера речи, отношения.
- **Включён** — выключенный агент не участвует и не попадает в аудиторию сцены.

Порядок слотов — порядок ходов. С каждой новой сценой круг начинается со следующего агента.

## Как это работает

1. Мастер пишет в чат обычное сообщение (не команду `/…`). Если автоответ включён, запускается цикл.
2. Агенты, которые находятся в сцене, по очереди выбирают одно действие: `pass` (промолчать, в чат не выводится), `say` (реплика), `ask_gm` (вопрос мастеру), `declare` (заявка). Каждый следующий агент видит ответы предыдущих.
3. Круги повторяются, пока не случится одно из событий: все в круге промолчали; все сделали заявку или задали вопрос; исчерпан лимит кругов или запросов; мастер написал новое сообщение (цикл начинается заново); мастер дал `/ai stop`.
4. В конце в чат выводится одна карточка «Заявки группы», видимая всем.

Пока агент думает, внизу чата висит строка «думает: Имя…».

### Что видит агент

- Системный промт: правила игры за столом, паспорт, выжимку листа (характеристики, навыки, снаряжение при себе, хиты/урон/эффекты, наличные), личные заметки этого агента и хронику кампании (последние ~6000 символов).
- Последние N сообщений чата, которые его персонаж мог видеть, в виде «Имя: текст». Сообщения мастера подписаны «Мастер», реплики NPC от токена мастера — «Имя (NPC)». Броски — как обычные сообщения: `[бросок 2d6 = 8]`.
- Не видит: шёпоты, слепые броски, мысли других агентов, служебные сообщения модуля и всё, что было в чате, пока его персонажа не было в сцене.

Как модуль узнаёт, кто был в сцене: на каждое новое публичное сообщение он ставит флаг `flags.ai-players.audience` со списком агентов, бывших в сцене. Сообщения без такого флага (написанные до установки модуля или когда активного мастера не было в игре) считаются видимыми всем.

### Где что хранится

| Что | Где |
|---|---|
| API-ключ | настройка клиента `ai-players.apiKey` (только в браузере мастера) |
| Агенты, состав сцены, сдвиг очереди | скрытые настройки мира |
| Секреты агента (`/ai tell`) | флаг `flags.ai-players.notes` на актёре агента |
| Хроника | журнал «ИИ-игроки: хроника», по странице на каждый `/ai recap` |
| Метки сообщений | флаги `flags.ai-players.*` на сообщениях (сообщения агентов цикл не запускают) |

Модуль не двигает токены, не меняет листы актёров, не трогает сцены и бой.

## Команды мастера

| Команда | Что делает |
|---|---|
| `/ai` или `/ai help` | список команд (шёпотом мастеру) |
| `/ai go` | запустить цикл вручную по последней сцене |
| `/ai stop` | немедленно остановить цикл; если кто-то уже сделал заявку, выводится карточка |
| `/ai next Имя` | дать слово одному агенту вне очереди (текущий цикл прерывается) |
| `/ai in Имя, Имя` | кто сейчас в сцене; `/ai in all` (или `все`) — все |
| `/ai tell Имя: текст` | секрет одному персонажу: сохраняется в его заметках, в чате виден только мастеру |
| `/ai recap` | сжать публичные события с прошлого recap в хронику (один запрос) и записать в журнал |
| `/ai status` | запросы и токены за сессию (с перезагрузки страницы), кто в сцене, модель, лимиты |

Имена ищутся без учёта регистра: сначала точное совпадение, затем начало имени, затем вхождение. Если подходит несколько агентов, команда сообщит об ошибке. Если в `/ai in` есть ненайденное имя, состав сцены не меняется.

Команды работают только у активного мастера. Игроку модуль ответит, что команды доступны только мастеру.

## Ошибки и расходы

- Ошибка API (неверный ключ, нет доступа, модель не найдена, лимит, перегрузка, сеть) приходит мастеру шёпотом понятным текстом, и цикл останавливается.
- Автоматических повторов нет, кроме одного: если ответ модели не разобрался (нет вызова `act`, неизвестное действие, пустой текст), запрос повторяется один раз, после чего ход считается `pass`, а мастеру приходит шёпот.
- Без сообщения или команды мастера модуль запросов не делает.
- Повторные круги одного агента частично читаются из кэша промтов (системный промт помечен `cache_control`). Это видно в `/ai status` как «из кэша».

## Ручная проверка в Foundry

Перед проверкой подготовьте мир на системе Mongoose Traveller 2e, в нём 4 актёра-путешественника (`traveller`) и ключ API Anthropic.

1. **Установка.** Включите модуль, перезагрузите мир. В консоли (F12) должна появиться строка `ai-players | game.system.id = "mgt2e" …`, и не должно быть красных ошибок с `ai-players`.
2. **Ключ.** Настройки модулей → ИИ-игроки → вставьте ключ. Убедитесь, что символы скрыты точками. Откройте мир вторым браузером под игроком: в его настройках ключа быть не должно.
3. **Агенты.** «Настроить агентов» → выберите четырёх актёров, заполните паспорта (например: «Цель — разбогатеть; боится полиции; говорит отрывисто»), включите всех → «Сохранить».
4. **Статус.** `/ai status` → шёпот: модель `claude-sonnet-5-5`, все четыре агента, «В сцене: все», 0 запросов.
5. **Первая сцена.** Напишите в чат обычный текст: «Таможенник поднимается по трапу и требует показать груз». Ожидаемо: появляется «думает: Имя…», агенты отвечают по очереди (реплики, вопросы, заявки — от имени своих актёров), мастеру шёпотом приходят мысли, в конце выводится одна карточка «Заявки группы» со строкой на каждого. В `/ai status` растут запросы и токены.
6. **Сдвиг очереди.** Напишите вторую сцену: первым должен заговорить второй агент списка.
7. **Прерывание.** Напишите сцену и, пока висит «думает…», напишите ещё одно сообщение. Старый цикл обрывается без карточки, новый начинается с учётом нового сообщения.
8. **`/ai stop`.** Запустите цикл и сразу дайте `/ai stop`. Цикл останавливается, мастеру шёпот «Цикл остановлен.».
9. **`/ai go`.** Выключите «Автоответ», напишите сообщение: цикл не стартует. Дайте `/ai go`: стартует. Включите автоответ обратно.
10. **`/ai in`.** `/ai in Имя1, Имя2` → шёпот с новым составом. Напишите сцену: отвечают только эти двое. Затем `/ai in all` и снова сцена: двое других не должны знать, что было в предыдущей (можно спросить их об этом напрямую).
11. **`/ai next Имя`.** Агент отвечает один, вне очереди.
12. **`/ai tell Имя: текст`.** Например `/ai tell Имя1: ты узнал в таможеннике своего брата`. Шёпот «🔒 Секрет…» видит только мастер (проверьте во втором браузере под игроком). На флаге актёра появилось `flags.ai-players.notes`. В следующих сценах этот агент может опираться на секрет, остальные о нём не знают.
13. **`/ai recap`.** В журналах появляется «ИИ-игроки: хроника» со страницей «Сессия …», мастеру приходит шёпот с текстом. Повторный `/ai recap` без новых сообщений отвечает «записывать нечего».
14. **Ошибки.** Впишите заведомо неверный ключ и напишите сцену: шёпот «Неверный или отозванный API-ключ…», цикл остановлен. Затем укажите несуществующую модель: шёпот «Модель … не найдена». Верните правильные значения.
15. **Игрок.** Под игроком напишите в чат: цикл не запускается, но агенты увидят это сообщение в следующем цикле. Команда `/ai status` от игрока даёт уведомление «Команды /ai доступны только мастеру».

## Автотесты (Node, без Foundry)

```bash
cd ai-players
npm test          # или: node --test "tests/*.test.js"
```

Нужен Node 18+ (проверено на 22). Зависимостей нет. Тесты гоняют настоящую связку «оркестратор → агент → API» с подставным `fetch` и проверяют:

- цикл останавливается, когда все сказали `pass`;
- цикл останавливается по лимиту кругов и по лимиту запросов (повтор не выходит за лимит);
- новое сообщение мастера прерывает цикл: запрос отменяется, запоздалый ответ в чат не попадает;
- агент вне сцены не вызывается и не видит сообщений этой сцены;
- секрет одного агента не попадает в контекст других;
- неразобранный ответ даёт один повтор, затем `pass` и шёпот мастеру;
- а также: `/ai stop`, `/ai next`, сдвиг очереди, ошибки API, заголовки запроса, счётчик токенов, разбор команд, выжимку листа `mgt2e`.

## Устройство

```
ai-players/
  module.json
  scripts/
    main.js            — хуки Foundry, команды, вывод в чат, хроника (только у активного мастера)
    orchestrator.js    — цикл сцены, очередь, прерывание и остановка (без Foundry)
    agent.js           — промт, инструмент act, разбор ответа, один повтор (без Foundry)
    api.js             — fetch к Anthropic, понятные ошибки, счётчик токенов (без Foundry)
    visibility.js      — кто в сцене, что видит агент, заметки, имена (без Foundry)
    commands.js        — разбор команд /ai (без Foundry)
    system-adapter.js  — всё, что зависит от Traveller (mgt2e); заготовка под броски
    settings.js        — настройки и окно агентов (ApplicationV2)
  styles/ai-players.css
  lang/ru.json
  tests/               — тесты на Node
```

**Броски (этапы 2–3).** Адаптер уже отдаёт `canRoll` и `rollCheck(actor, rollRequest)`. Для этапа 2 достаточно реализовать `rollCheck` в `system-adapter.js` (в `mgt2e` есть `game.mgt2e.rollSkillMacro(skillFqn, { actor })`) и добавить кнопку «Разрешить бросок» в карточку в `main.js`. Остальной код менять не придётся.

## На чём проверено и что не проверено

API Foundry сверялся с описаниями типов сообщества `foundry-vtt-types` версии v13.345.1. Структура данных `mgt2e` сверялась с исходниками системы (`Mongoose-Publishing/traveller-foundryvtt`, версия 0.24.0.0). `main.js` прогонялся на макете Foundry. В настоящем Foundry модуль не запускался: сайт и дистрибутив Foundry из среды разработки недоступны. Поэтому начните с ручной проверки выше.

Места с пометкой `// TODO: проверить`:

1. `settings.js`: учитывает ли окно настроек v13 опцию `input` (поле-пароль). Если нет, поле всё равно станет паролем через хук `renderSettingsConfig`.
2. `main.js`: имя поля в окне настроек (ожидается `ai-players.apiKey`) для этого хука.
3. `system-adapter.js`: как на этапе 2 вызывать бросок `mgt2e` (открывает ли `rollSkillMacro` диалог, как передать DM).
